## **2. 业务背景与目标**

### **2.1 背景**

#### **2.1.1 业务痛点**

现有数据中台（Spring MVC 5.3 / JSP）报表体系存在结构性矛盾：

- **需求侧**：PM / 运营的数据分析需求高频、多变，常需要跨维度的临时分析，例如“对比两个产品 ROI 或金币复购率差异”。
- **供给侧**：每张报表依赖后端手工开发，周期数天至数周，且报表上线后利用率低，形成“开发资源浪费”与“PM 等待”的双输局面。

#### **2.1.2 已验证的解法**

产品团队已在大模型上形成一套可行的分析工作流：

1. 从数据中台导出 Excel / CSV
2. 打开大模型 AI 对话框，上传文件
3. 粘贴结构化 Prompt（角色 + 分析框架 + 指标口径定义）/ 选择预制的 Skill
4. 大模型在内置 Python 沙箱中读文件、计算指标、输出报告
5. PM 多轮追问，大模型迭代补充分析

**核心结论**：真正被验证的不是“自然语言直接查数据库”，而是**把一份结构化数据集交给 LLM + Python 分析执行环境，通过多轮对话持续产出分析结论**。

### **2.2 目标**

本方案目标不是从零开始自研一套 AI BI 平台，而是：基于现有 `Local Overview Report` 报表快速嵌入 AI 分析工作台，把已在 LLM 上验证过的分析流程产品化、权限化、可复用化，实现“查数即分析，分析可沉淀”。

## **3. 功能需求（含 P0/P1/P2 优先级）**

### **3.1 模块一（P0）：报表页侧边AI辅助分析入口**

维度

说明

**功能描述**

在 `Local_overview_Report` 页面右侧提供悬浮入口，点击展开 AI 辅助分析对话框（抽屉形态）。进入时默认注入当前报表的查询上下文（时间范围、筛选维度、分页数据样本）。提供“固定场景卡片”与“自由自然语言对话”双模式。

**前置条件**

1\. 报表数据已加载完成且非空\
2\. 用户具备当前报表 `data-read` 权限\
3\. AI 服务节点网络连通

**操作步骤**

1\. 点击右侧悬浮按钮\
2\. 抽屉滑出，顶部展示当前查询上下文摘要\
3\. 用户点击预制场景卡 或 在底部输入框输入自然语言\
4\. AI 流式返回分析结果，支持视图切换、导出、转存\
5\. 针对结果继续输入追问，AI 基于上下文迭代输出

**预期结果**

抽屉内完整呈现多轮对话流；AI 输出支持动态切换为 `a-table` 或 `ECharts`；支持一键转存为历史任务；上下文记忆连贯不丢失。

**数据规则**

\- 注入参数：`{ timeRange, filters, sampleRows: 50, metrics: ['DAU','ROI','金币复购率'] }`\
\- 上下文窗口：保留最近 10 轮对话，支持 `@清除上下文`\
\- 状态管理：Pinia 隔离存储，页面刷新不丢失未转存草稿

### **3.2 模块二（P1）：AI辅助分析任务列表**

维度

说明

**功能描述**

独立路由模块，集中展示当前用户已转存的历史 AI 辅助分析任务。支持按任务名称、基准产品、创建时间筛选。

**前置条件**

用户已登录，且至少完成过一次“转存”操作

**操作步骤**

1\. 进入【AI辅助分析任务】菜单\
2\. 使用顶部搜索框或下拉筛选器过滤记录\
3\. 点击操作列 `查看详情` 跳转详情页

**预期结果**

`a-table` 规范渲染任务列表，含任务名、创建时间、基准产品、状态（进行中/已完成）；支持分页、批量删除与一键导出清单。

**数据规则**

\- 存储结构：`{ taskId, title, createdAt, baselineProduct, status, lastPrompt, resultSnapshot }`\
\- 权限：严格行级隔离，仅返回 `userId = current_user` 的记录

### **3.3 模块三（P1）：AI辅助分析任务详情（80/20 布局）**

维度

说明

**功能描述**

展示历史转存任务的完整分析成果。页面严格采用左右 `80%/20%` 分割布局。左侧呈现最终分析结果仪表盘，右侧保留历史对话上下文与追问输入框。

**前置条件**

从任务列表点击有效 `taskId` 进入

**操作步骤**

1\. 页面加载自动请求历史结果快照与对话记录\
2\. 左侧渲染 ECharts/表格，右侧按时间轴滚动展示历史问答\
3\. 在右侧输入框输入新指令，AI 基于历史快照生成新分析并实时刷新左侧视图

**预期结果**

布局比例锁定 `80% : 20%`；右侧支持 Markdown 渲染与快捷指令；左侧视图随 AI 新输出平滑切换，支持二次导出。

**数据规则**

\- 视图状态由 Pinia `aiResultStore` 管理，支持视图类型切换持久化\
\- 对话流采用增量追加策略，避免全量重渲染导致卡顿

类别

约束说明

**性能**

### **🔒 硬性约束（开发实施规范）**

1. **技术栈**：严格使用 `Vue 3 Composition API + <script setup>`、`Ant Design Vue 4.x`、`ECharts`、`Pinia`。
2. **标注规范**：所有可交互 DOM 必须添加 `data-marker` 属性（如 `data-marker="lp_ai_trigger"`），页面底部强制内置折叠面板汇总标注映射。
3. **交互范式**：AI 对话框交互逻辑、流式响应渲染、工具栏布局需深度参考 `DB-Chat` 设计，保持 B 端数据产品一致性。
4. **路由与菜单**：路由注册为 `/Local_overview_Report`，左侧菜单新增对应项，激活态与当前路径严格同步。
5. **代码结构**：新页面置于 `src/views/Local_overview_Report.vue`，AI 对话/任务组件拆分至 `src/components/`，保持高内聚低耦合。
